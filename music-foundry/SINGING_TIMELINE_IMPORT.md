# Singing render → Music Foundry timeline import\n\nThis bridge reuses the existing Music Foundry take manifest and offline assembler. It does not create a second timeline or mixer.\n\n## Flow\n1. Complete and human-review the existing vocal score using the vocal score editor.\n2. Run the existing SoulX local runner to produce generated.wav and singing_render_manifest.json.\n3. Import that verified render into the existing take timeline:\n\n```bash\npython3 music-foundry/import_singing_render.py \\n  --render-manifest path/to/singing_render_manifest.json \\n  --output-manifest path/to/imported-take/spoken-takes.json \\n  --offset-ms 30236 \\n  --project-duration 105.827 \\n  --layer gang_vocals\n```\n\nThe offset is an editorial placement decision, not inferred from the score. Use the approved phrase placement. The displayed song duration is the current 56-bar, 127-BPM arrangement and must be recalculated if tempo or arrangement changes.\n\nThe importer verifies render schema, project identity, SHA-256 checksum, and exact mono 24 kHz / 16-bit PCM WAV format required by the existing assembler. It copies the source WAV unchanged into a local takes folder and writes the established spoken-takes manifest. The copied WAV can then be used by assemble_spoken_takes.py and the existing browser timeline.\n\n## Boundaries\n- No audio, lyrics, phonemes, notes, or timing are altered or inferred.\n- No existing file is overwritten.\n- A human chooses the vocal layer, gain, pan, and placement.\n- This bridge currently targets Somebody's Gotta Do It and the existing assembler's 16-bit PCM input contract.\n- This is an integration contract, not proof that SoulX has rendered a real take.
