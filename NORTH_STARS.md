# TURBO ECOSYSTEM — NORTH STAR LEDGER

> **Purpose:** track what each meaningful system is trying to prove, not how impressive its repository looks.
>
> **Rule:** implementation volume is not progress. A North Star advances when a reproducible proof event occurs.

## Maturity vocabulary

- **DEMONSTRATED** — the core claim is reproducibly expressed by working software/evidence inside its stated scope.
- **OPERATIONALIZING** — substantial implementation exists; the decisive proof event or deployment breadth remains incomplete.
- **EXPERIMENTAL** — machinery exists, but the hypothesis still needs prospective/real-world evidence.
- **ROADMAP** — specified direction without enough implementation to claim the capability.
- **RECOVERY** — historical capability/artifact is believed to exist but has not been located or deliberately migrated.
- **LEGACY / PLACEHOLDER** — preserved for history; not a current capability claim.

These labels are deliberately conservative. They are not percentages, grades, or promises.

## Proof-event doctrine

A proof event should be:

1. **Observable** — a reviewer can see what happened.
2. **Reproducible where practical** — inputs, versions and procedure are preserved.
3. **Bounded** — it proves only the claim it actually tested.
4. **Prospective when prediction is involved** — no rewriting the rule after the outcome.
5. **Truth-labeled** — simulation, prototype, testnet, paper, live and settled are never conflated.
6. **Authority-aware** — research output does not silently become permission to spend, trade, deploy, sign or control hardware.
7. **Failure-preserving** — failed experiments remain evidence.

## Interpretation rule

This ledger is a control surface, not marketing.

- **DEMONSTRATED** does not mean finished forever.
- **EXPERIMENTAL** is not a criticism; it means evidence is still being earned.
- A large repository does not outrank a small reproducible proof.
- A failed preregistered experiment can advance the ecosystem more than an untested feature.
- When the ledger conflicts with current code/evidence, update the ledger to match reality — never the reverse.
